# RPC PDU Control 0.1.2

This release makes user actions visible in Homebridge logs while keeping routine status traffic quiet.

## Normal logs

- Accepted On, Off, and native Reboot commands, with the configured PDU name, outlet number, and outlet name.
- Power-aware requests that need no command because the outlet is already in the requested state.
- One message when a fresh post-delay status confirms power On after a power-aware action, and a warning if the recovery window ends without confirmation.
- Existing warnings and errors, including uncertain command outcomes.

Acceptance is not the same as confirmed power or a fully booted device. An uncertain command is never logged as accepted; subsequent On confirmation does not prove that an uncertain reboot occurred.

## Debug logs

HomeKit state reads and results, cache hits, shared refreshes, fresh status requests, recovery reads, and successful startup/periodic polling checks. Enable Homebridge debug logging for the instance or child bridge running the plugin to see them. Routine successful reads and polling generate no info-level traffic.

Credentials and raw Telnet exchanges are excluded. Logging adds no PDU requests and changes no polling, caching, session limits, or native reboot behavior. Logger failures cannot turn accepted commands into failures or retries.

## Update

Select **latest** in Homebridge UI, or use `sudo hb-service add homebridge-rpc3control@latest` on an hb-service-managed Linux installation, then restart Homebridge. No configuration migration is required.
