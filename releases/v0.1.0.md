# RPC PDU Control 0.1.0

First stable release of homebridge-rpc3control, bringing BayTech RPC PDUs into Apple Home through Homebridge. This promotes the beta.2 functionality; existing beta.2 configuration and outlet behavior are preserved.

## Included

- One or more PDUs with configurable physical outlet counts and individually named switches.
- Normal On/Off switches and power-aware reboot switches that display confirmed outlet power state.
- Native PDU reboot: once accepted, the PDU handles power off and back on even if the reboot interrupts the network or Homebridge host.
- Homebridge UI configuration with PDU cards, outlet generation, timing controls in seconds, and a read-only connection/status preview.
- Shared status caching, optional periodic polling, and bounded read-only recovery checks.
- Direct Telnet communication with no Python, Pexpect, Script2, or external Telnet program.

## Install or update

In Homebridge UI, search for **homebridge-rpc3control** and install **latest**. Existing beta users should select **latest** through **Manage Version**.

For an hb-service-managed Linux installation, use `sudo hb-service add homebridge-rpc3control@latest`, then configure and restart through Homebridge UI. See the [README](https://github.com/pponce/homebridge-rpc3control#installation) for the complete instructions.

## Upgrade behavior

Beta.2 users keep the same behavior. When upgrading from beta.1, reboot switches now display actual outlet power: request On to power up an Off outlet, or request Off to reboot an On outlet. Update any scenes or automations that previously requested On to reboot. The PDU restores power itself; the recovery check delay only controls when status verification begins.

## Compatibility and validation

Requires Node 22.13+ within version 22, or Node 24; Homebridge 1.8+ within version 1, or Homebridge 2.x. Automated validation covers simulated PDUs, Homebridge lifecycle behavior, browser configuration, and packaged plugin loading. Other RPC models are assumed to share the Telnet interface and four-session limit but remain hardware-unverified. This release does not claim additional physical hardware testing.
