# RPC PDU Control 0.1.1

This maintenance release fixes error-handling gaps found while reviewing Homebridge verification requirements.

## Fixes

- A failing status callback no longer produces an unhandled rejection or leaves a waiting status request unresolved. Other outlets still receive status updates, and a successful PDU operation stays successful.
- Both synchronous callback exceptions and rejected callback promises are caught and logged without exposing raw error details or credentials.
- Failed accessory setup is caught at startup. Partially created controllers are stopped, cached accessories are preserved and marked unavailable, and no polling starts before setup completes successfully.
- Cleanup continues when an individual resource fails. Reboot recovery callbacks and background operations also have error boundaries.
- Added regression tests for the failure paths above.

## Documentation

The project icon now appears above the README title. The icon's appearance in Homebridge plugin search remains subject to Homebridge's verification/icon approval process.

## Update

Select **latest** in Homebridge UI, or run `sudo hb-service add homebridge-rpc3control@latest` on an hb-service-managed Linux installation, then restart through Homebridge UI. No configuration changes or accessory identity migration are required.

Power-aware reboot still uses the PDU's native reboot command. Recovery timers only check status; they never send a delayed On command or automatically repeat a reboot.
